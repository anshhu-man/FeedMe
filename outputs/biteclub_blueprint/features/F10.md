# F10 — Keep the Vibe

Phase: first release. Owner modules: catalog, planning.

## Strategy

When an ingredient is unavailable, preserve the sensory reason the person wanted it through a reviewed substitute. “No cucumber? Keep the crunch” is the signature example, but compatibility and actual preparation matter more than a catchy label. One supported alternative is preferable to an unverified list.

## Experience and screen design

RECIPE and VARIANT show an ingredient-level Not available action. For a sensory addition, the button can use the approved sensory label, such as Keep the crunch. ADAPT confirms the missing item and preserves the current time, effort and exclusions. VARIANT displays one replacement, an honest description of the difference, affected quantities/steps and revised effort. Choose replacement commits the proposal for subsequent cooking; Keep original returns without changing pantry inventory. If no substitute fits, offer Change taste or Something else. Marking one ingredient unavailable can optionally update pantry through a distinct confirmation.

## Production sequence

1. Pin the recipe version, targeted ingredient requirement and sensory intent.
2. Enumerate reviewed substitution edges for that exact recipe or supported template version.
3. Validate replacement availability, ingredient-component exclusions, step preconditions, equipment, portion conversion and effort.
4. Reject substitutions that require an unsupported second substitution or incomplete recipe rewrite.
5. Return a fully materialized variant with a stable version reference; preserve the original preference memory even when its ingredient is unavailable today.

## Data and API contracts

Use adaptPlan POST /v1/plans/{planId}/adaptations with an explicit substitution intent and normal revision/idempotency headers.

    {"reason":"missingIngredient","replaceIngredientId":"00000000-0000-4000-8000-000000000011","retainTasteTag":"crunch","constraints":{"ingredientIds":["00000000-0000-4000-8000-000000000012"],"energy":"assemble","equipmentIds":["bowl","knife"],"servings":1,"hardExcludedIngredientIds":[],"tasteTags":["crunch"],"maxTotalMinutes":5}}

Return Plan.changes entries with fromIngredientId, toIngredientId, substitutionId and explanation, plus the complete resulting recipeSnapshot for quantities, steps and effort. Internal substitution records pin reviewed source versions, supported serving bounds and conversion proofs. A ratio alone is insufficient if instructions or equipment change. noMatch or recall errors explain why no permitted substitute can be offered. The current constraints.ingredientIds omits unavailable ingredients; this request does not permanently change F03 pantry or F16 preferences. Retrying another substitute extends the bounded presented-variant history.

## Permissions and lifecycle

Only published reviewed substitution versions enter planning. A community tip or language model suggestion cannot create a reviewed edge. Source recipe and variant saveability follow their respective grant and catalog access rules. A new version never silently changes an immutable saved recipe; safety recalls can block its use through the explicit recall contract.

## Failure and offline behavior

Offline users may view downloaded substitution variants already included in their authorized recipe bundle; unknown conversions are unavailable. If one substitute also becomes unavailable, add it to the current exclusion-from-availability list and search remaining supported options without looping. An empty graph ends with a clear choice, not an invented swap. Stale plan conflicts keep the original recipe visible until refreshed.

## Integration and dependencies

F06 provides sensory intent, F03 availability, F04 hard exclusions, F11 effort recomputation and F13/F51 review/versioning. F01 Make Mine calls the same substitution engine. F16 memory keeps “liked cucumber with noodles” separate from “no cucumber today.”

## Execution plan

- Implement versioned substitution edges and materialized variant validation.
- Add quantity/step integrity checks for every reviewed serving range.
- Build ingredient-level unavailability and comparison interactions.
- Emit substitution_requested/resolved/rejected with review IDs and generic reason codes; omit private preference values.

## Acceptance and release gates

Test hidden excluded components, a swap adding a cooking step in assembly mode, unsupported serving conversion, chained substitutions, two unavailable options and retention of original liked-combination memory. Reviewers must approve the whole resulting preparation, not just ingredient equivalence. Gate substitution edges individually; withdraw a faulty edge immediately while preserving unaffected recipes and alternatives.
