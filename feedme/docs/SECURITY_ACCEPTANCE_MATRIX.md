# FeedMe security acceptance matrix

M7.01 test specification · 13 September 2026 · **server/provider/device cases below are NOT RUN**.

This is a concrete implementation and release test contract, not a passed security report. It covers the full retained blueprint through parameterized route/action coverage plus adversarial cases. Read [THREAT_MODEL.md](THREAT_MODEL.md) for boundaries, source links, residual risks and unresolved C01–C04 decisions. No new API endpoints, policy approvals or production controls are established here.

## Canonical references and execution rules

Use the [98-screen / 900-action registry](../../outputs/biteclub_blueprint/registry/screen_registry.json), [button binding CSV](../../outputs/biteclub_blueprint/registry/button_actions.csv), [201-operation OpenAPI](../../outputs/biteclub_blueprint/architecture/04_API_Contract.json), [data invariants](../../outputs/biteclub_blueprint/architecture/03_Data_Model.md), [security rules](../../outputs/biteclub_blueprint/architecture/10_Security_Privacy.md), [events](../../outputs/biteclub_blueprint/architecture/05_Events.md) and [runbooks](../../outputs/biteclub_blueprint/architecture/09_Production_Runbooks.md). The IDs below are canonical. Screen loads are named explicitly as hydration; external SDK actions have no invented FeedMe API operation.

For every execution retain: case ID; source/build SHA and artifact hash; API/schema/config/retention-policy revisions; platform/OS; real adapter versus fake; synthetic actor/resource IDs; setup state; exact redacted request; observed status and safe response shape; database/object/event deltas; negative assertions; test command; timestamp; and result `PASS`, `FAIL`, `NOT_RUN` or `POLICY_BLOCKED`. Capture failures as well as passes. Use non-secret request hashes and trace IDs, never credential values or personal payloads in evidence.

Release acceptance requires more than a status code: unauthorized reads must contain no protected body, source label, media capability or identifying count; denied writes must cause no domain mutation, side-effect event, push, export or entitlement grant. Audit/rate-limit records may be created only within the approved redacted policy. Run valid-owner controls first so a broken/unimplemented service cannot "pass" by rejecting everything. Recheck immediately after the race's commit boundary, not after an arbitrary sleep.

### Evidence layers

- **L** — shared local unit/property tests and explicit demo behavior; no network authority claim.
- **S** — API plus real isolated database/worker/storage-adapter integration, including direct calls that bypass UI.
- **N** — Android and iOS native lifecycle/device tests against the intended adapter; emulator-only or simulator-only evidence stays labeled.
- **P** — approved provider/store sandbox or configured staging evidence, then a separately authorized production configuration check.
- **O** — operator-reviewed policy, incident, retention, moderation or restore drill; no legal sufficiency inferred from software tests.
