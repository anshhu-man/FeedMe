## Contract and implementation boundary

The wire authority is the [canonical API JSON](/Users/LOCAL_USER/Documents/ChatGPT/Career/outputs/biteclub_blueprint/architecture/04_API_Contract.json), especially PostDraftWrite, PostDraftPatch, PostDraft and PostDraftPage. Older descriptive uppercase draft phases are not substituted for the canonical wire states `draft`, `published`, `discarded`, `expired`.

All five operations require actual UserBearer verification and a registered `X-Device-Session`. Guest identity and the public invitation-preview exception do not authorize drafts.

| Operation | Exact method/path | Request controls | Successful response |
| --- | --- | --- | --- |
| createPostDraft | POST `/v1/post-drafts` | Idempotency-Key; PostDraftWrite, whose sole required field is clientDraftId | 201 PostDraft; ETag of its version |
| listPostDrafts | GET `/v1/post-drafts` | Optional cursor and limit; HTTP default 20, range 1–50 | 200 PostDraftPage; ETag of the owner's list revision |
| getPostDraft | GET `/v1/post-drafts/{draftId}` | Exact UUID path | 200 PostDraft; ETag of its version |
| updatePostDraft | PATCH `/v1/post-drafts/{draftId}` | Original Idempotency-Key and If-Match; PostDraftPatch | 200 PostDraft; new version ETag |
| deletePostDraft | DELETE `/v1/post-drafts/{draftId}` | Original Idempotency-Key and If-Match; no body | 204; no body or ETag |

There is no conditional 304 branch. The ingress rejects undeclared query/conditional controls, duplicate or ambiguous authentication/framing, invalid UTF-8/JSON, unsupported encodings and malformed exact versions. It bounds request bodies at 65,536 bytes and JSON depth 32, validates the canonical schema before projection, validates returned status/body/ETag, and uses `no-store`. Caption and altText retain the schema's 500-Unicode-scalar bound; no extra media-count quota is invented.

## Required transaction-sharing authority

[PostDraftAuthority](/Users/LOCAL_USER/Documents/ChatGPT/Career/feedme/server/src/main/kotlin/com/feedme/server/social/drafts/PostDraftAuthority.kt) has no accepting implementation or fallback. The HTTP verifier establishes the claimed account/device/environment; the store then requires fresh database authority, including before receipt disclosure. Production integration must implement all four methods on the supplied connection:

- `lockPrincipal`: exclusive current account/device lifecycle lock shared with media, circles and account deletion. A once-verified token is not current eligibility.
- `requireMutationEnabled`: current community terms, account eligibility and draft-save policy. Turning off new posting/upload must not unnecessarily prevent existing owned reads or cleanup.
- `lockDraftLifecycle`: the same stable owner/clientDraftId root and positive generation used by MediaAuthority and processing authority. A generation is an incarnation, not the editable draft version.
- `authorizeContent`: current circle membership/block policy and exact attachment/source read or redistribution rights. New selection and retained viewing are distinct checks. Client rightsBasis, reviewStatus and Audience.bindings are not proof; a private recipe copy or cooking pin is not permission to redistribute it.

Callbacks must not open a second transaction, commit, perform network I/O, mutate input or emit effects. Every cooperating lifecycle writer must honor this order:

`principal → command receipt → owner list head → clientDraft lifecycle → PostDraft → content/circle authority → media rows in UUID order`

Use same-connection policy seams, not a successful public CirclesStore/MediaStore preflight followed by a separate draft commit. Account/device revocation, block/membership changes, upload/worker admission, draft deletion and eventual publication must serialize against the relevant same roots.

The explicit `PostDraftLifecycle.requireEditable` helper is for upload/worker adapters while holding that shared root lock. When a PostDraft exists, it must still be `draft` and unexpired before effects are admitted. An absent row neither creates an implicit PostDraft nor grants permission by itself: the media authority still checks the owned upload lifecycle. A terminal observation/cleanup path is not renewed upload authority.

[PostDraftServicePolicy](/Users/LOCAL_USER/Documents/ChatGPT/Career/feedme/server/src/main/kotlin/com/feedme/server/social/drafts/PostDraftModels.kt) requires caller-selected response bytes 1–262,144, draft lifetime 1–2,592,000 seconds and cursor lifetime 1–86,400 seconds. These are explicit service bounds, not account quotas, a selected production retention policy or consent. Store and HTTP environments must match the configured MediaStore environment. Cursor keys are also explicit: one to eight named 32-byte keys, including the current signing key; the class defensively copies them. Actual identity, terms, source-rights and circle/block implementations and key management remain integration obligations.

## Private lifecycle and durable command behavior

Create allocates one server draft for the stable owner/clientDraftId, with version 1. Minimal input persists caption empty, mediaIds empty, Only-you audience, keepOnPlate false and allowRecipeSaves false. This is private draft initialization, not publication. Explicit optional input is retained under schema and authority checks; client Audience.bindings are stripped, not promoted into server audience generations. Duplicate media/circle identities and attachment plus removeAttachment=true are rejected.

Patch preserves absent fields, applies explicit false values, and uses removeAttachment=true to remove the attachment. It cannot change clientDraftId. An admitted edit, including an empty patch, increments the version and sets a fresh configured expiry after current authorization. Failed or stale edits do not renew it. Creating another command key never silently recycles an existing, expired, discarded or published clientDraftId.

GET and list create no draft/root, renew no lifetime, issue no upload capability and append no command/event. List returns only owned, currently editable, unexpired drafts. Each selected item's current content authority is checked, with fresh-time expiry checks after callbacks; denied content fails the page rather than leaking or silently substituting items. GET of a discarded row is 404; expired is 410. The store can reconcile an already-published terminal row, but this package has no publisher: the published-state regression is an explicitly synthetic lifecycle fixture, not publication proof.

[DurableCommands](/Users/LOCAL_USER/Documents/ChatGPT/Career/feedme/server/src/main/kotlin/com/feedme/server/db/DurableCommands.kt) binds the owner, operation, original key, path, body and original If-Match. JSON semantic equality is preserved; textual object-key order is not an API guarantee. A changed body/path/precondition under the same key mismatches. An exact create/update replay additionally requires the current matching draft result and current retained-content authority: it cannot acknowledge a later edit or resurrect an expired draft. A replay does not advance version, expiry, owner head or outbox.

The domain row, list head, original command receipt and internal event commit atomically. Responses are canonically validated and size-checked before mutation commit; create/update reserve 256 bytes for a one-item page. An oversized list fails explicitly with RESPONSE_TOO_LARGE rather than truncating an apparently complete page; a smaller requested limit is available. Existing successful command receipts retain their seven-day protocol. Expired receipts are not permission to manufacture a replacement key.

Public failures are finite/redacted: missing owned draft 404, conflict 409, expiry 410, version conflict 412, invalid data/response size 422 and unavailable 503. Missing required If-Match is 428 at ingress. Command mismatch, expired receipt and incomplete command remain distinct typed failures. Unknown commit maps to 503 OUTCOME_UNKNOWN and requires original-command reconciliation. Cancellation/interruption is preserved across database work and after commit; a cancelled caller or absent HTTP response never proves that the command did not commit.

## Pagination is continuation, not authority

[PostDraftCursors](/Users/LOCAL_USER/Documents/ChatGPT/Career/feedme/server/src/main/kotlin/com/feedme/server/social/drafts/PostDraftCursors.kt) signs the configured environment, owner, owner-head revision, requested limit, last UUID and expiry. Pages use deterministic UUID order. Changed owner/environment/limit/head, malformed values or unknown keys are rejected; a correctly signed expired cursor returns 410. Current principal/content checks still run on every continuation. A cursor is neither a bearer grant nor a frozen authorization snapshot.

The emitted cursor deadline is bounded by the configured cursor lifetime and the selected drafts' expiry. Reading never extends a draft lifetime or revives an expired input cursor. PostDraftPage includes items, nullable nextCursor and serverTime. The list ETag represents the owner list head, not any individual draft's writable version; clients must not use it as a PATCH/DELETE If-Match.

Owned DELETE accepts an unpublished draft or stored expired state at the exact current version, even when new posting, attachment reading or upload permission is unavailable. It does not permit deleting a published post through the draft route. One transaction changes the draft to discarded, increments its version, records the original deletion key, clears its private content to the sole internal terminal format `{}`, and retains owner/client/version/cleanup correlation. GET remains unavailable; no fabricated empty PostDraft body is returned. Earlier successful command receipts still have normal retention, so this is not instant erasure of all database, backup or client copies.

The narrow same-connection [MediaStore](/Users/LOCAL_USER/Documents/ChatGPT/Career/feedme/server/src/main/kotlin/com/feedme/server/media/MediaStore.kt) helper validates selected assets against the exact owner/root/generation and current unattached state. Editable drafts may retain awaitingUpload, processing, rejected or ready metadata; none is publication readiness. Discard visits **all** media in that root, including uploads omitted from the current mediaIds and previously individually deleted assets. An attached asset aborts the whole transaction; unrelated roots remain untouched. Already-deleted media keep their original public deletion receipt.

Deletion preserves exact quarantine version/deadline and bounded derivative cleanup targets through V007/V008. [PostDraftCleanupEvidence](/Users/LOCAL_USER/Documents/ChatGPT/Career/feedme/server/src/main/kotlin/com/feedme/server/social/drafts/PostDraftCleanupEvidence.kt) pins each media version plus immutable processing-job, write-intent and cleanup-target identities. Replay compares that evidence and exact root membership; missing/altered targets or cleanup flags fail closed. It never repairs missing cleanup or equates absence with successful deletion. Actual cleanup progress and acknowledged late object writes may advance while the same immutable target remains; a late upload-event ingestion is allowed only as a cancelled job without new derivative intents or changed targets.

Already-issued upload/write capabilities can outlive logical discard until their original acceptance deadlines. The tombstone immediately denies new admission, while purpose-fixed cleanup retains the late-effect targets. The 204 acknowledges durable metadata and cleanup intent, **not completed object erasure**. Actual immutable-object, worker-purpose, safety/moderation, bounded provider-I/O and cleanup execution integrations remain mandatory; synthetic race fixtures do not supply them.

The only new event is [social.post_draft.changed.v1](/Users/LOCAL_USER/Documents/ChatGPT/Career/feedme/server/src/main/kotlin/com/feedme/server/social/drafts/INTERNAL_EVENT_CONTRACT.md): producer social, aggregate post-draft, schema 1, exact environment/ownerId/draftId/version/state data.
