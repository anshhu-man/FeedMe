# F38 — Short Clips

## Strategy
Short Clips let people show a quick cooking action or the dish they made. This later feature serves recipe understanding and personal sharing, without requiring video to participate. Initial proposed limits are 15 seconds and 50 MB of source media, with server-side validation and a readable text alternative. These are product defaults to load-test, not verified provider limits.

## Experience and screen design
`CAPTURE` offers camera or system-library selection. `VIDEO_EDIT` provides trim handles, preview, mute-original-audio, caption text, and an accessible description. The duration and upload estimate appear before continuing to F31’s audience and publication preview. `STORY` and `POST` use tap-to-play with sound off by default, native pause/seek controls, captions, and reduced-motion support. The user can share a still image or text instead if encoding fails. Source clips from someone else’s post are never automatically offered as remix material.

## Production sequence
`POST /v1/media` reserves an owner-bound video upload slot with declared size/type/hash. After byte upload, `POST /v1/media/{mediaId}/complete` verifies object ownership and checksum and commits `media.upload_completed` to the outbox. An idempotent worker inspects actual format and duration, strips embedded location metadata, scans content, transcodes approved playback variants, and generates an owner-scoped poster. It commits either `READY` with a versioned manifest or `FAILED` with a safe reason. `GET /v1/media/{mediaId}` lets the owner inspect readiness. `POST /v1/posts` in F31 succeeds only when all selected media is ready and authorized.

## Data and API contracts
`Media(id,ownerId,draftId,kind,state,sourceBytes,verifiedDurationMs,contentHash,manifestVersion,processingAttempt,errorCode)` uses `RESERVED`, `UPLOADED`, `PROCESSING`, `READY`, `FAILED`, `DELETED`. `MediaVariant(mediaId,variantId,mimeType,dimensions,storageKey)` references private objects. `POST /v1/media/{mediaId}/access` authorizes the post surface and returns a temporary signed bearer URL with TTL at most 60 seconds, further bounded by that surface’s remaining lifetime. Typed errors include `MEDIA_TOO_LONG`, `MEDIA_TOO_LARGE`, `UNSUPPORTED_FORMAT`, `PROCESSING_FAILED`, and `MEDIA_UNAVAILABLE`. Worker deduplication keys include media ID and manifest version so retries cannot publish partial output.

## Permissions and lifecycle
Camera and microphone permissions are requested only when those actions are chosen; library access uses native limited selection where possible. Denying microphone still permits a silent clip. Raw uploads and transcodes remain private before publication. Deletion or audience revocation immediately denies new API reads and signed URLs. An already issued signed URL can remain usable for its residual TTL of at most 60 seconds, and a transfer already started can finish. This limitation must be stated accurately; downloaded frames cannot be remotely erased. Clients stop playback and clear buffers on invalidation. Urgent removal separately purges origin derivatives and invalidates CDN objects.

## Failure and offline behavior
Editing works on user-selected local files without publishing. Resume interrupted uploads through renewed owned slots, and cap local/background retries according to platform lifecycle constraints. If the app is killed after completion, `PUBLISH_STATUS` recovers processing state from the draft. A failed transcode preserves the local draft and provides retry, replace, or remove; never publish an unprocessed source file as fallback. Network transitions stop automatic playback rather than unexpectedly consuming cellular data.

## Integration and dependencies
F31 composer, F40 authorization, F42 moderation/deletion, native media APIs, private S3 storage, CloudFront signed delivery, outbox workers, and F54 telemetry. The private origin is inaccessible without its configured CDN access control. URL lifetime, deletion behavior, and codec support require implementation proof on both platforms before release.

## Execution plan
Prototype native selection/editing on Android and iOS; implement upload validation and deterministic processing; build short-lived signed playback with fresh authorization; integrate reporting, deletion, accessibility, and resource budgets. Observe processing latency, failure reasons, playback stalls, and bandwidth without storing captions or signed URLs in logs.

## Acceptance and release gates
Test forged MIME types, oversized/overlong clips, rotated video, missing audio, app termination, worker redelivery, revoked access, expired signed URLs, and denied permissions. `media.video_upload.enabled` stops new videos; `media.video_playback.enabled` independently denies new playback capabilities while preserving deletion and text alternatives. Require cross-device visual/audio QA and measured confirmation of the documented residual-URL window, without claiming instantaneous remote erasure.
