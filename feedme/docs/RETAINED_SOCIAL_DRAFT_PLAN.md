# Retained social draft client: next implementation package

Planning only, 2026-09-14. Written while the tenth `recalled-copy-drafts` verification run is source-frozen. This file is not evidence that a composer client, native composer screen, publication, media provider or release integration has passed. It changes neither the 44-feature V1 scope nor the canonical contracts. The proposed package is the retained, account-private draft foundation of F31; the remaining F31 workflow stays open.

## Smallest useful boundary

Implement actual encrypted local caption/alt-text editing and explicit canonical server draft create, list, read, update and discard. A retained controller borrows the existing authenticated session and shared command journal. It neither owns another native store nor initializes a worker. Native UI can then render this controller without inventing a second draft model.

Local persistence is not server Save. Server Save is not Share. List/read, restoration, navigation and reconnect are not permission to submit. No publication endpoint, attachment grant, media upload/camera permission, audience mutation, Keep-on-Plate mutation or automatic expiry deletion is added in this package. Existing canonical fields on a remote draft must remain intact, even where the first editor has no control for them.

### Exact operation boundary

| Explicit action | Existing operation | Required retained identity and result |
|---|---|---|
| Save a new local draft to the server | `createPostDraft` | Stable `clientDraftId`; new logical-command UUID; exact `PostDraftWrite` bytes; bind `201 PostDraft` and its ETag to that client identity. |
| Load a server page | `listPostDrafts` | Account/device; opaque cursor and original page limit only; `200 PostDraftPage` plus independent owner-list-head ETag, including `"0"`. No `q` parameter exists. |
| Refresh an exact server draft | `getPostDraft` | Exact `draftId`; `200 PostDraft` and representation ETag. Observation is not an acknowledgement of a lost mutation. |
| Save changed text on a server draft | `updatePostDraft` | Exact original draft ID, quoted If-Match, command UUID and caption/alt-text patch bytes; bind `200` to the same client/server identity and submitted base. |
| Confirm server discard | `deletePostDraft` | Exact draft ID, original quoted If-Match and command UUID; only bound bodyless, ETag-less `204` acknowledges discard. |

The canonical wire status is `draft`, `published`, `discarded` or `expired`; it is separate from local journal phase and editor state. GET can return `published`; create/update return `draft`. Do not infer or write a publication transition. Keep decimal versions exact, including values beyond floating-point precision; never synthesize a replacement If-Match from a rounded or incremented UI number.

## Reuse actual ownership, not a parallel queue

The current `MealKitchenComposition` has one coroutine-scoped operation owner, exact access/boundary/origin, a fenced store/transport and one `PrivateKitchenSession.commands`. Cooking and cookbook borrow it. Add a purpose-fixed `POST_DRAFTS` borrower to that same composition. Do not construct a second `DurableCommandQueue` over the same journal or expose the cooking generation wrapper as a general-purpose store.

Proposed additive seams, to be assigned to one integration owner before editing:

- `PostDraftCommandHooks` in `shared/kitchen`: `executionDecision(lease, intent)` and `observeReply(lease, intent, reply)` for **only** `createPostDraft`, `updatePostDraft`, `deletePostDraft`. A new optional constructor dependency on `PrivateKitchenSession` defaults to denial, not an accepting implementation. The existing cooking and saved-recipe hooks stay unchanged.
- Add that hook and the exact five-operation transport allowlist to the `POST_DRAFTS` branch of `MealKitchenComposition`. Hook execution requires the exact active borrower/operation. Its reads must not recursively enter the controller/composition mutex. Siblings cannot dispatch the draft's command, and a draft retry cannot drain cooking/cookbook commands.
- Add an explicit factory such as `MealKitchenControllers.createWithDrafts(..., draftPolicy)` returning a typed bundle containing the three retained controllers over **one** composition. Keep the existing two-controller factory usable and default-denied for draft operations. Do not bolt a standalone composer factory onto an already-open bundle in a way that creates a second journal owner. The exact public factory name is a proposal, not a landed API.
- No `SessionWorkRegistry`, `PrivateSessionRuntime.install`, native work ticket, timer, scheduler or cancellation-port changes are necessary for explicit foreground HTTP and local editing. Future background dispatch would require a separate approved lifetime/effect integration; the journal alone does not provide it.

Current `CommandPolicy` already assigns all three draft mutations `FRESH_CONFIRMATION`. Preserve that policy, including the existing social FIFO lane. `dispatchConfirmed(lease, originalId)` is the explicit submission path; neither `dispatchAutomatic` nor `dispatchNext` becomes a draft autosave worker. The queue's current six-day conservative replay cutoff and eight-attempt limit remain client policy, not a new server promise or permission to delete uncertain intent.

## Proposed retained model and controller

Use new isolated `shared/mealflow/.../social/` files: `PostDraftController.kt`, `PostDraftModels.kt`, `PostDraftRecords.kt`, with an internal exact response/mutation adapter if needed. Reuse `WireDocument`, `MobileRequestValidator`, `CanonicalResponseBinder`, `ApiCall`, `ApiReply` and the existing private store acknowledgement wrapper. No new module/dependency or raw-store public API is necessary.

Suggested public actions are `restoreLocal`, `newLocalDraft`, `editText`, `openLocal`, `listRemote`, `nextRemotePage`, `refreshRemote`, `saveExplicitly`, `prepareServerDiscard`, `confirmServerDiscard`, `retryOriginal`, `discardUnsent`, `discardLocal` and `close`. Destructive confirmation is a process/owner-bound ticket containing exact identity/revision, not serializable consent. No public `publish` or arbitrary `execute(ApiCall)` action is exposed.

Keep these facts distinct in immutable state:

- Local `clientDraftId`, exact caption/alt-text edits and local revision; acknowledged local persistence versus an unacknowledged edit still retained in this owner.
- Last verified complete canonical server document, its exact ETag, and whether it is historical. A page observation is not a downloaded local draft or a mutation receipt.
- The immutable original command: operation, command ID, client/server draft IDs, origin/scope, original body/path/If-Match, submitted local revision and baseline fingerprint. No credentials, provider tokens, upload capabilities or arbitrary server messages enter it.
- Any newer local edits, which do not alter the queued body or original base. A late original Save receipt updates only the correlated baseline; it cannot overwrite the newer edit or display it as server-saved.
- Pending/unknown/needs-resolution/receipt-ready/applied-but-local-ack-unknown state and finite safe issues. A restored APPLIED archive is historical, not a new-process acknowledgement.

Use a versioned, bounded private namespace/index plus exact local-delete/server-discard tombstones. All decoded identities, schema, byte counts, capacities and record fingerprints must be checked before execution. New drafts get fresh IDs through the injected ID source only after admission; terminal `clientDraftId` is never recycled. Preserve fields the text editor does not own by sending only explicit text patches; do not rebuild a remote document from visible controls or copy server-only audience bindings into a write.

## Durable actions and recovery

1. **Local edit:** retain the proposed edit in memory before awaiting storage. Commit with expected revision and require exact changed-CAS/result/readback acknowledgement. A fresh create accepts a positive returned revision, not a fabricated revision of one. Missing/malformed/failed ACK leaves the edit visibly unacknowledged, not silently discarded by close/reopen in the same lease. No network or native work is touched.
2. **Explicit Save/discard admission:** pin generation, lease, origin, selected client/server ID, exact local revision and baseline/ETag before any wait. Check account-only access, online mode/connectivity, current configured operation and the exact immutable local record. Check local capacity before creating an ID or sending. Local offline work stays local; it is not submitted merely because connectivity returns.
3. **Original durable command:** atomically `enqueue` the original request, domain pending record and any reservation/index changes. One unresolved original command for the editor is sufficient for this first package; additional local drafts/edits may remain local. Do not coalesce an attempted command or bypass the shared queue's social ordering. `discardUnsent` applies only when the queue confirms zero attempts.
4. **Explicit dispatch:** the fixed draft hook rechecks the exact persisted command and current owner immediately before queue dispatch. The actual account transport supplies current credentials and registered device information. Application configuration is not server authorization: the server still checks account/device, terms, draft-save switch, draft incarnation and referenced content. Back/close/cancellation before sending prevents a late dispatch; after sending, none proves rollback.
5. **Receipt apply:** bind operation/status/media type/schema/body/ETag, then require original journal `intent()` equality before preparing domain mutations. Create must match `clientDraftId`; update must match both IDs/base and explicit patch while preserving unrelated content; delete must be exactly bodyless `204`. Apply the prepared result, baseline/index/tombstone and queue archive with `applyReceipt` in one acknowledged batch. No mandatory extra GET is needed to accept a valid Save receipt.
6. **Lost apply ACK:** retain the actual prepared mutations and actual queue archive mutation captured by `beforeCommit`, bound to the exact lease. Original-ID finalization checks exact domain/archive payloads and revisions before and after a fresh changed CAS. Never reconstruct proof from APPLIED, a GET or a matching status. Preserve an explicit unresolved/reconciliation state if proof is unavailable after process death; restoration must not invent new consent or an ACK.
7. **Unknown dispatch/restart:** `recoverInterrupted` reclassifies without sending. Explicit original retry uses the same key/body/path/ETag and original age, with current preflight. `403/404/409/410/412/422`, expiry, clock rollback, exhausted retries or a changed server baseline require visible resolution, not rebase/key rotation. GET may help the user inspect current state but cannot clear the original command as successful. The current backend may reject replay after a later edit/expiry; that is not evidence the earlier command never committed.
8. **Discard:** distinguish unsent local removal from server discard. Server `204` atomically removes the exact cached draft and preserves a non-resurrection marker plus original command identity; it does not delete unrelated drafts, meals, saved recipes or cooking. An expired owned server draft can still be cleaned with retained original metadata and explicit consent; do not require successful content GET first. Unknown DELETE retains its original identity. New drafting after terminal discard is a separate explicit intent with a fresh `clientDraftId`.

## Privacy, cancellation and observations

The controller is retained before first I/O and uses the actual borrowed session's serialized dispatcher. Every store/transport await has pre/post generation and exact-lease checks, including caller-return publication. `SessionBoundary.onInvalidated` synchronously clears caption, selection, pages, consent and ACK projection. Preserve inaccessible durable records for the real session retirement/recovery owner; controller close never erases scopes, closes native stores, releases application reservations, revokes credentials or claims remote cancellation.

Unacknowledged edits/finalization evidence that survive same-lease editor replacement need an exact-lease owner-scoped holder. Reuse the established immutable-list atomic membership pattern if a process registry is necessary; independent session dispatchers do not globally serialize a mutable singleton. Clear only the invalidated lease's entry and handle synchronous invalidation during subscription registration.

Separate local index browsing from explicit remote pages. Preserve one bounded current page and bounded traversal IDs/cursors, not an unlimited downloaded list. Pin page request generation, cursor and limit; reject repeats/duplicate IDs, regressions and same-version/different-body observations. Owner-list-head ETag is not an item ETag. A mutation or changed head invalidates traversal and requires explicit refresh; missing an item from a page is not deletion. Older read completions cannot resurrect local tombstones, overwrite newer edits or re-show content after an authoritative negative response. A bound collection denial identifies no individual draft and must not manufacture per-ID deletion authority.

## Required composition inputs and unresolved decisions

Required inputs are the actual verified `PrivateSessionAccess` (ACCOUNT only), exact boundary/dispatcher, explicit canonical account transport for the configured environment, connectivity, clock, ID source and a bounded `PostDraftClientPolicy`. The public access adapter may reuse `AuthenticatedMealPlanningAccess.fromSession`; it is borrowed composition, not an authentication provider. No synthetic identity, test transport, accepting gate or optional default provider is installed in production.

The client policy must explicitly supply local draft/index/history/byte and issued-ID capacities, read-page/traversal limits, and treatment of retained unsent local drafts. These are resource/privacy bounds, not invented feature quotas. Do not override the queue's uncertainty retention or the server's expiry with a client eviction. A live service still needs actual `PostDraftHttpConfiguration`, verifier, `PostDraftAuthority`, cursor keys and media/lifecycle adapters; the optional backend path/default application does not furnish those integrations automatically.

Resolve these before expanding the package or choosing product defaults:

- F31's data paragraph still uses proposed 30-day retention and old uppercase states; the JSON/03 state machine uses lowercase canonical statuses. Architecture 03 additionally says thirty days since last edit, while the current service policy permits a configured lifetime up to thirty days and renews `expiresAt` on a successful update. Preserve returned server expiry and its uncertainty; do not silently choose local auto-deletion, renewal, grace or notification behavior. No expiry worker is implemented by a draft UI.
- Recipe attachments, redistributable-source grants, media readiness/capabilities, audience membership and disclosure are not proved by a private cookbook copy or cooking pin. Do not enable those edits until their actual reviewed policy/composition is supplied. Text-only new drafts can use the established owner-only/self semantics without widening an audience; remote non-text fields remain untouched.
- Publication requires a separately reviewed immutable request, current media/rights/audience checks and deliberate Share. The saved-server-draft branch additionally carries its exact draft/version; the canonical no-server-draft branch must not be silently removed. See the [two-branch publication review](POST_PUBLICATION_CONTRACT_REVIEW.md). Five draft operations and `publishedPostId` observations do not implement either transaction or unknown-result reconciliation. No full F19/F31, iOS, physical process durability or background-delivery completion claim follows from this foundation.

## Implementation ownership and acceptance

Assign the fixed hooks plus the two existing composition/bundle files to one shared integration owner. A second owner can implement the new isolated controller/models/records and common tests after that API freezes. A third can add real-SQL and canonical-HTTP integration tests; root retains all build/device/run ownership. Native screen/host composition is the following package, not concurrent speculative wiring. No changes to session/work ownership, queue policy, storage drivers or historical verification runners are required by this proposal.

Before calling this foundation accepted, require:

- Pure/schema tests for all five operations, exact large versions/ETags, canonical status versus UI state, Unicode/byte bounds, text-only patches preserving every unrelated field, no provider secrets in stored records/diagnostics and no implicit publish/GET/save from rendering or restore.
- Real encrypted SQLite integration through the actual runtime/access and shared composition: local changed-CAS/readback/tombstone revisions; corrupt/missing/reordered results; suspend before/after commit; same-lease editor replacement; read-return/caller cancellation; unknown enqueue/dispatch/apply; exact archive-proof finalization and proof corruption; reboot/reconstructed owner with historical rather than new ACK; exact account/origin isolation.
- Deterministic edit-during-Save and late list/get tests; original bytes/ID/ETag survive newer edits, 412, 410, clock change and explicit retry. Double clicks allocate one command. Back/close/lease invalidation at every await prevents late publication of state or dispatch. Unknown outcomes cannot be discarded through an unsent path. Capacities fail before irreversible calls; paging never skips into fictitious success or tombstone resurrection.
- Shared-queue tests: draft cannot execute another feature's command, sibling gates remain default-denied, social FIFO is respected, no recursive mutex deadlock, no second queue/store owner, no background/native scheduling or automatic reconnect submission.
- Configured real PostDraft HTTP/PG loopback: exact create201/update200/list/get200/delete204, owner-only/non-enumerating responses, original replay after lost response, later-resource/expiry rejection, page-head/cursor changes, terminal/new-client identity, content denial and expired-owner cleanup. Fixture authority is explicitly synthetic; production provider availability remains separate.

Pin final test inventories only after implementation. Central focused tests, exact current-source full verification and later actual native retained-host/restart evidence are separate gates; this plan claims none of them.
