# F40 — Audience Controls

## Strategy
Audience Controls make sharing scope explicit and revocable. Initial production audience types are `SELF` and `CIRCLES`; no public feed or discoverable public profile is implied. A post’s audience is independent of its lifespan and recipe-copy policy. This feature is a hard prerequisite for all social and coordination releases, not a cosmetic picker.

## Experience and screen design
`AUDIENCE` shows “Only you” and individually selected active Kitchen Circles, with names and member counts. The preview explains that current and future members of those selected circles may see still-available content. `PRIVACY` changes the default for future drafts. `POST` lets its owner edit the active audience and preview added or removed circles. Narrowing or expanding existing access requires an explicit Save; merely visiting a picker changes nothing. The screen separately links to `SAVE_PERMISSION` and explains that earlier authorized recipe copies survive audience changes.

## Production sequence
`GET /v1/circles` supplies eligible choices. `PATCH /v1/post-drafts/{draftId}` saves the draft audience with `If-Match`; publication rechecks it under F31. `PATCH /v1/posts/{postId}` with `{audience}` authorizes the owner, locks the post, validates current memberships, increments `audienceVersion` and post version, and writes `post.audience_changed` in the same transaction. The API returns the committed audience summary; clients invalidate feeds and active media. `PATCH /v1/me/privacy` can update `defaultAudience`, which is copied into future drafts for review rather than retroactively applied to posts.

## Data and API contracts
`Audience(kind,circleIds)` uses wire values `self` with no circles or `circles` with distinct active circle IDs. `PostAudience(postId,circleId,authorMembershipGeneration)` has a unique post/circle constraint. `AccessDecision` evaluates account state, authorship, post status, placement, current membership generations, and no block in either direction. Membership and block changes invalidate authorization caches. DTOs expose only audience details the viewer may inspect, never hidden alternate circles. Typed errors include `AUDIENCE_INVALID`, `CIRCLE_UNAVAILABLE`, `VERSION_CONFLICT`, and generic `POST_UNAVAILABLE`.

## Permissions and lifecycle
Viewer access is permitted by any selected circle still valid for author and viewer, with blocks taking precedence. Author departure revokes that circle’s post grants; rejoining does not silently restore the previous membership generation. Narrowing takes effect at commit for new API reads and signed-URL issuance. Existing signed URLs may remain usable for their residual TTL of at most 60 seconds, and started transfers can finish, as specified in F38. Downloaded pixels cannot be remotely erased. A take shared more broadly never automatically includes original source media.

## Failure and offline behavior
Audience edits may be drafted offline but must show “Not updated yet” until acknowledged. Never display a privacy reduction as completed locally while remote access remains active. On conflict, show current versus proposed scope and require review before resubmitting. If a selected circle disappears before publishing, preserve the draft and ask the author to select a valid audience; never default to all circles. A stale deep link returns `UNAVAILABLE` without revealing whether a block, removal, or deletion caused it.

## Integration and dependencies
F21/F22 placement rules, F23 membership generations, F30 grants, F31 publication, F38 protected media delivery, F42 blocks, and F54 access auditing. Coordination records reuse the authorization service but keep their explicit participant or circle scopes.

## Execution plan
Implement a shared server authorization policy and membership-generation records; then picker and edit previews; then transactional invalidation and protected delivery enforcement. Audit decision outcomes by opaque IDs and reason category without logging circle names or media captions.

## Acceptance and release gates
Test multiple audiences, author departure/rejoin, viewer removal/rejoin, block precedence, concurrent edits, expired Today versus retained Plate, and broader-audience remixes. `social.sharing.enabled` stops new grants while narrowing, deletion, and private cooking remain available. Release requires request-time API authorization, accurate residual-media-window disclosure, and no scope widening on any fallback path.
