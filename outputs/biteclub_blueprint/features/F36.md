# F36 — Shortcut Swap

## Strategy
Shortcut Swap lets someone share a specific way they reduced effort, cleanup, or equipment for a dish. The value is a useful personal tip with clear source and review status. Peer tips are not automatically professionally reviewed and cannot rewrite the app’s reviewed recipe steps. This later feature includes private tip saving, optional acknowledgement, reporting, and author withdrawal.

## Experience and screen design
`SHORTCUT_CREATE` asks for an accessible recipe and a short original tip. The preview states that permitted tip text may be privately saved, while source-recipe permissions remain separate. `SHORTCUT_DETAIL` shows the source only when authorized, a Personal tip or reviewed-status label, Save this tip, Helpful, and Add to my cooking notes. A personal note is visibly separate from instructions in `COOK`. “Make Mine” separately opens the normal reviewed adaptation flow in `ADAPT`. Publishing previews the selected audience and never includes original source media automatically.

## Production sequence
`POST /v1/shortcuts` validates source access and original text rights, stores the chosen audience, and emits `shortcut.created`. `GET /v1/shortcuts/{shortcutId}` authorizes tip and source context separately. `POST /v1/shortcuts/{shortcutId}/saves` creates a permitted private text snapshot; `POST /v1/shortcuts/{shortcutId}/helpful` stores one reversible actor acknowledgement. Add to notes uses `PATCH /v1/cook-sessions/{sessionId}` with `personalNotes`, source-tip ID, and `If-Match`; the transaction authorizes the owned session, writes only the note, and emits `cook_session.notes_changed`. It never invokes recipe adaptation from unreviewed tip text. `DELETE /v1/shortcuts/{shortcutId}` withdraws an owned tip; corrections publish a new tip after preview.

## Data and API contracts
`Shortcut(id,authorId,recipeVersionId,text,audience,status,version)` contains plain text, not executable transformations. Review status comes only from a bound review record; a Helpful reaction cannot change it. `SavedShortcut(ownerId,sourceShortcutId,sourceVersion,textSnapshot,createdAt)` never includes recipe content or media. `CookSession.personalNotes` is a distinct private field outside pinned ingredients, steps, timers, and review provenance. Unique actor/shortcut save and acknowledgement constraints prevent duplicates. `TIP_UNAVAILABLE`, `SAVE_NOT_ALLOWED`, `SESSION_NOT_OWNED`, and `VERSION_CONFLICT` are typed results. Durable actions use idempotency keys and payload hashes.

## Permissions and lifecycle
Visibility requires current membership, no block, and an active shortcut. Source content is independently scoped. A saved third-party recipe permits private use but not republication of inherited recipe text; the shortcut shares only the author’s original note and an authorized reference. Withdrawal stops new tip reads/saves but follows the disclosed persistence policy for authorized private text snapshots. Safety/legal recalls can suppress affected notes on sync. A newly reviewed correction never silently rewrites someone’s recipe, note, or saved version.

## Failure and offline behavior
Compose a tip offline as a private draft. Publishing and new saves require access validation. Existing authorized private notes can be edited offline through the session’s normal queue; conflicts preserve both texts for user review. A timeout retries the same save/note key. An unavailable source becomes a neutral source label, never a cached media fallback. Separately requested Make Mine still uses current hard exclusions and reviewed substitutions; a tip cannot weaken them or change a timer automatically.

## Integration and dependencies
F01 adaptation, F08 Make It Easier, F10 Keep the Vibe, F13 review provenance, F30 recipe grants, F40 audience controls, and F42 reporting. An optional own-media post still uses F31 publication, linked to the shortcut by ID.

## Execution plan
Implement tip provenance and permitted text snapshots; build authoring/detail and own acknowledgement states; add private note fields to cooking sessions without changing pinned recipe structure; then integrate review labels, withdrawal, and reporting. Track duplicate suppression, note conflicts, and review-label mismatches without logging note text.

## Acceptance and release gates
Test source revocation, private-copy versus text-tip rights, replayed saves, note conflicts, peer-versus-reviewed labels, withdrawn tips, and hard-exclusion behavior in the separate Make Mine route. `coordination.shortcuts.enabled` disables new creation/saving while retaining private notes and withdrawal. Release requires proof that unreviewed tip text never mutates reviewed recipe steps, ingredients, timers, or review status.
